# whatsapp-mcp-kit

A setup kit that lets an AI assistant (Claude Code, Codex or any MCP client) read your WhatsApp chats and send messages, using your own account.

**Who it's for:** people who want their AI assistant to work with WhatsApp.
**What you get:** WhatsApp linked to your AI tools through one small local service, plus ready prompts so an agent does the setup.

> **Account risk, read first:** this uses an unofficial WhatsApp client (Baileys). WhatsApp can restrict accounts that use such clients, so a separate number is safest. Your assistant will also see the messages you let it read.

## Quick start
1. Open Claude Code or Codex in an empty folder on the machine that should read WhatsApp.
2. Paste the block from [`PROMPT.md`](PROMPT.md) (Russian versions: [Claude Code](PROMPT-CLAUDE.ru.md), [Codex](PROMPT-CODEX.ru.md)). Read it first: the agent checks what you already have, explains the risk once, installs one shared local service and opens a QR page.
3. On your phone: **WhatsApp > Settings > Linked devices > Link a device**, scan the page.

**Done when:** you send yourself a fresh test word in WhatsApp and the agent reads that exact word back.

> Want an AI agent to do it for you? Paste this to Claude Code / Codex / Cursor:
> "Read the 'For AI agents' section of https://github.com/tonydzi/whatsapp-mcp-kit and set it up for me."

## For AI agents

### Preconditions
- The ready-made prompt for you is [`PROMPT.md`](PROMPT.md) (English); Russian: [`PROMPT-CLAUDE.ru.md`](PROMPT-CLAUDE.ru.md), [`PROMPT-CODEX.ru.md`](PROMPT-CODEX.ru.md). The full runbook is [`README.ru.md`](README.ru.md) (Russian). Read the runbook and the prompt from the same revision before acting.
- Tools: `node` (a supported LTS), `npm`, `git`, Python 3. Windows, macOS or Linux.
- Account: the human's own WhatsApp on their phone. Only they can scan the QR.
- Ask the human: which WhatsApp account to link (a separate number is recommended) and whether they accept the account-restriction risk; this is asked once.
- First do a read-only inventory: existing WhatsApp MCP definitions in both clients (`claude mcp list`, `codex mcp list`), running processes, existing data folder, listening port. If a working install exists, use it and do not reinstall.

### Install
From the runbook (`README.ru.md`, sections 2 to 4). Replace `<KIT_DIR>`, `<SERVER_DIR>` with folders you choose. `<MCP_DIR>` below means `<SERVER_DIR>/node_modules/@sjawhar/whatsapp-mcp`. In Windows PowerShell 5 run `mkdir` and `cd` as two separate lines (no `&&`):
```bash
git clone https://github.com/tonydzi/whatsapp-mcp-kit <KIT_DIR>
mkdir <SERVER_DIR> && cd <SERVER_DIR>
npm init -y
npm install --save-exact @sjawhar/whatsapp-mcp@2.4.0
```
Then, inside `<SERVER_DIR>/node_modules/@sjawhar/whatsapp-mcp`, run `git apply --check <KIT_DIR>/patches/0001-qr-raw-to-stderr.patch` and only then apply it (check patch 0002 separately). Make a Python venv in `<KIT_DIR>/.venv` and install `qrcode pillow` there. Do not run `npm update` and do not run the server with `--help`: some versions connect to WhatsApp at once.

### Configure
- Private env values for the pairing step: `WHATSAPP_MCP_DIR` (installed package folder), `XDG_DATA_HOME` (private per-account data folder), `WA_QR_WORK_DIR` (temporary QR files).
- Pair: `python <KIT_DIR>/pair/wa_qr_live.py --check`, then `python <KIT_DIR>/pair/wa_qr_live.py`, and show the human the local page it prints.
- `<ACCOUNT_PORT>` is a free local port you pick (one per account). Run one owner service per account: `node <MCP_DIR>/dist/index.js --http --host 127.0.0.1 --port <ACCOUNT_PORT>`, with `MCP_API_KEY` and `ALLOWED_SEND_DIR` set from a protected environment (the key is generated by you and stays out of git and argv). Never bind `0.0.0.0`.
- Connect both clients over HTTP to `http://127.0.0.1:<ACCOUNT_PORT>/mcp` using `configs/claude-http.example.json` and `configs/codex-http.example.toml` as examples. Codex: `codex mcp add whatsapp --url http://127.0.0.1:<ACCOUNT_PORT>/mcp --bearer-token-env-var WA_MCP_TOKEN` (`WA_MCP_TOKEN` must hold the same string as `MCP_API_KEY` in the environment that starts Codex).

### Verify
Offline checks (no phone, no network, safe to run):
```bash
python pair/wa_qr_live.py --selftest
python pair/test_wa_qr_live.py
```
Expected: `SELFTEST PASS` and `ALL GREEN (52 checks)`, both exit 0 (run here: matched). These prove only the QR helper's logic; they pass with no WhatsApp linked, so they are not the install check. The live proof below is.
Live proof: the human sends a fresh unique word to a chat they chose, and both clients read exactly that word back, again after a controlled restart of your own owner service. A port, cached profile, old chat list or exit 0 is not proof. Report static, configured, paired, live read, live send and recipient acknowledgement separately.

### Uninstall / rollback
Stop and remove only the service you created. Remove the two MCP entries you added (back up the client configs before editing). To unlink: on the phone, WhatsApp > Linked devices > remove the device. Delete the private data folder only with the human's explicit say-so; never delete `auth_info` to bypass a check.

### Rules for the agent
- Never print or store the QR, pairing code, bearer key, `auth_info`, SQLite files or chat contents in logs, reports or git.
- Never copy auth state to another machine, never start a second WhatsApp connection on the same data folder, never kill other `node` processes.
- Sending a message to anyone needs the human's approval for that exact address and text. After a send timeout the status is unknown: search for the message before retrying.
- Do not invent flags (there is no phone-code CLI in this kit); use only what the runbook and `--help` of local scripts show.

## Details

Connect Claude (Claude Code / Claude Desktop / Codex — any MCP client) to **a WhatsApp account** so it can read your chats and send messages. Includes portable setup skills, prompts, private pairing, shared HTTP configuration and recovery instructions.

(The 3-step start moved to the top of this page.) Built and battle-tested at [Palo Alto AI Research Lab](https://github.com/tonydzi/tonydzi) — our Claude fleet has been reading WhatsApp through exactly this setup since June 2026.

## Current setup for Claude Code and Codex

Read the [complete runbook (Russian)](README.ru.md), then use the [Claude Code prompt](PROMPT-CLAUDE.ru.md) or [Codex prompt](PROMPT-CODEX.ru.md). Install the portable [whatsapp-connect skill](skills/whatsapp-connect/SKILL.md) for future sessions. Both clients connect to one loopback HTTP service; they must not each launch a full WhatsApp connection.

The skill installs with one command. Claude Code, as a plugin:

```
/plugin marketplace add tonydzi/whatsapp-mcp-kit
/plugin install whatsapp-mcp-kit@whatsapp-mcp-kit
```

Any agent that reads Agent Skills (Claude Code, Codex, Cursor, Gemini CLI):

```bash
npx skills add tonydzi/whatsapp-mcp-kit
```

This installs the setup skill only. The WhatsApp service itself is still installed by the steps above.

This is one linked-device stack: [`@sjawhar/whatsapp-mcp`](https://github.com/sjawhar/whatsapp-mcp-2.0) + Baileys. Multiple accounts need separate private data roots and owners. The unofficial-client account restriction risk and access to private message content must be understood before linking; see [security](docs/SECURITY.md).

### Pinned setup and pairing

The runbook uses isolated npm installation of version **2.4.0**, checked historical patches, private environment storage and one operational supervisor. Its HTTP branch has **no built-in account lock** in that release; do not start another owner manually or through a second service. The docs distinguish this operational rule from enforced exclusion.

The [QR helper](pair/wa_qr_live.py) holds stdin open and renders a refreshing local PNG page. It now rejects nonempty draft credentials: saved account/Signal-identity structure is required. That is persisted-state evidence, not fresh network connectivity. Prove a new incoming nonce in each AI client after startup and restart. A port, cached profile, old chat list or exit 0 does not prove live delivery.

For code-based phone pairing see the [bounded prompt](PROMPT-PHONE-CODE.ru.md). Baileys has the API; this kit does not yet ship a ready phone-code CLI. Do not invent flags for the MCP server or launch a second socket on the same auth directory.

### What is tested

Offline synthetic regression covers draft/invalid persisted state, QR parsing and helper process behavior. New phone pairing, a fresh three-OS installation and recipient acceptance have **not** been rerun for this documentation update. Preserve these limits in your own report.

Do not run remote prompts blindly or enter secrets in an agent conversation. Follow [pairing documentation](pair/README.md) with the selected package bytes. Phone errors can have several causes; expiry is one possible cause, not a diagnosis from the wording alone. History depth is not guaranteed: measure actual sync rather than assuming a complete archive.
